What collapses

A built-in user bubble whose rendered content (text, markdown, code, attachments) is taller than maxHeight is clipped with a bottom fade and a real <button>. Content within about two lines (48px) of the limit stays expanded, so the toggle never hides just a line or two. The full message stays in the DOM, so find-in-page, copy, selection, and screen readers still reach it. It is off by default in V4 and on under future.v5Defaults.

features: { userMessageCollapse: { enabled: true, maxHeight: 240 }, }, copy: { showMoreLabel: "Show more", showLessLabel: "Show less" }, theme: { components: { userMessageCollapse: { fadeHeight: "48px", toggleForeground: "#2563eb", toggleFontSize: "0.8125rem", toggleFontWeight: "600", }, }, },

Moving the toggle

The toggle sits at the start of the bubble's text, under the last visible line. It keeps its own width, so an auto margin in your stylesheet pushes it across. The placement control above swaps exactly these rules in a page stylesheet.

/* Align to the bubble's end edge */ .persona-user-collapse-toggle { display: flex; margin-inline-start: auto; } /* Or center it */ .persona-user-collapse-toggle { display: flex; margin-inline: auto; }

Accessible by default

The button carries aria-expanded and aria-controls pointing at the clip region, and focusing into a collapsed message expands it. A reader's choice is remembered per message for the life of the widget, and interim voice transcripts stay expanded until they are final.

Hooks for host CSS

The clip region carries data-persona-user-collapse="fit" | "live" | "collapsed" | "expanded" and the button data-persona-user-collapse-toggle with the .persona-user-collapse-toggle class. See "Long user messages" in THEME-CONFIG.md for the token table.
