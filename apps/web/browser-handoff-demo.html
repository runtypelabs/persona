Browser Handoff

An agent driving a remote browser parks on a login it can't do, embeds the live session in the transcript, and picks the run back up when you're done. The pause is a real step_await; the resume is a real /resume.

Try it

Sends a message through the composer. The mock backend answers with a local_tool_required pause for wait_for_human_handoff, which renders the card and blocks the run until you answer it. Add ?live=1 to the URL to dispatch to the local proxy's WebMCP route instead.

Embedded in the card's iframe. Most sites refuse framing via frame-ancestors; example.com allows it. A real Cloudflare Browser Run live view URL works here too, and expires after about five minutes.

The same registered renderer, reached the other way: a tool-result artifact with artifactType: "component". It needs display.byType.component: "inline" to land in the thread rather than the side pane.

Notes

How the run parks

wait_for_human_handoff is a WebMCP page tool on document.modelContext, so the widget ships it to the agent as a LOCAL tool on every dispatch. When the model calls it the server emits a step_await with awaitReason: "local_tool_required" and closes the SSE stream — the run is parked, not dropped. The widget then runs the tool's execute() in the browser; ours returns a promise that stays pending until you click a button on the card, and its result is POSTed to ${apiUrl}/resume to continue the conversation.

Why the card never re-renders

The iframe holds a live, single-use browser session, so rebuilding the card would drop your work. ComponentContext.updateProps is a no-op in the transcript, and re-injecting the directive rebuilds the subtree — so the renderer runs exactly once and every later state change mutates the mounted DOM through closure references. The widget stamps the wrapper data-preserve-runtime="true", which makes idiomorph skip the subtree on subsequent render passes.

Embedding caveats

A site that refuses framing still fires the iframe's load event with a browser error page inside it, and cross-origin means the page can't inspect the result — so the card always offers "Open in a new tab" as a first-class fallback, and warns after eight seconds if nothing has loaded at all.
