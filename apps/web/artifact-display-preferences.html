Artifact display

Choose where each artifact group appears. Use default follows the application’s current setting; any other choice saves your override.

File type exceptions

Only file types with a declared or observed exception need to appear here.

Inherited QA baseline

  • README stays a collapsed card via Other artifacts.
  • Chart is inline via Registered UI components.
  • HTML app is inline via a visible HTML exception.
  • Logo follows the image/* wildcard once you set one.
  • CSV data opens in the panel via Generated files.

How this maps to Persona

UI labels → config keys

This selector is host-owned UI over Persona’s features.artifacts.display configuration.

Generated files
display.files
Registered UI components
display.byKind.component
Other artifacts
display.default
HTML files
display.files.byMediaType["text/html"]
Images
display.files.byMediaType["image/*"]

Direct feature config

Applications without saved user preferences can configure the behavior directly: 

const config = {
  features: {
    artifacts: {
      display: {
        default: "collapsed",
        byKind: { component: "inline" },
        files: {
          default: "panel",
          byMediaType: {
            "text/html": "inline",
            "image/*": "inline",
          },
        },
      },
    },
  },
};

Which rule wins?

Layers merge with one rule: an object refines lower layers per key, while a string value replaces the whole subtree it names. So a user-level files: "inline" overrides every lower-layer file exception, and files: { default: "inline" } keeps them. Persona then tests the merged rules from most specific to least specific:

  1. Exact MIME type
  2. Wildcard MIME type (image/*)
  3. Generated file default
  4. Artifact kind
  5. The artifact’s own preferredMode hint
  6. Configured default
  7. Persona default: panel

Preference API

baseFeatures remains code-owned and contains capabilities, renderers, callbacks, and iframe security. Preference layers are sparse JSON objects containing display choices only.

Choosing Use default passes null, which deletes that user key. It does not save the currently resolved mode, so future application-default changes still flow through.

Data loaded from storage can be passed through parseWidgetPreferenceSlice. Unknown or invalid keys are reported and removed before they reach feature config. 

const store =
  createFeaturePreferenceStore({
    base: baseFeatures,
    layers: [{ id: "app", preferences: appDefaults }],
    stored: loadFromStorage(),
    onChange: ({ features, preferences }) => {
      handle.update({ features });
      saveToStorage(preferences);
    },
  });

store.setArtifactDisplay(
  { type: "files" },
  "inline", // null resets this choice
);

Explain the result

The reference controls use Persona’s public resolver rather than duplicating fallback logic. It returns the effective mode, the selector that matched, and the layer that supplied that selector. 

const result =
  resolveArtifactDisplayPreference(
    baseFeatures.artifacts,
    [
      { id: "app", preferences: appDefaults },
      { id: "user", preferences: userPreferences },
    ],
    {
      artifactType: "markdown",
      file: {
        path: "app.html",
        mimeType: "text/html",
      },
    },
  );
