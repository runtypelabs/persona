What the plugin owns

One plugin implements two hooks. renderWelcome returns the form while identity is missing and null once it exists, so Persona's own welcome card takes the surface back. renderComposer returns a disabled composer while gated and null after submit. Nothing in the widget package changes: this is example code in apps/web/src/plugins/pre-chat-plugin.ts.

Unlocking the composer

The composer hook runs once at panel construction, so the unlock rides its requestRender(): the core re-runs composer arbitration and swaps the footer in place, re-wiring attachments, mentions, and the listener registry. The welcome hook's own requestRender() drops the form in the same tick.

renderComposer: ({ config, storage, requestRender }) => { adoptStorage(storage); composerRequestRender = requestRender; if (readIdentity()) return null; // default composer return buildGatedComposer(config); }

Where the identity goes

Submit does three things: writes the identity through ctx.storage, injects a compact identity line with controller.injectSystemMessage() so the transcript context reflects it, and exposes a contextProviders entry so every dispatch carries the fields. Context providers run on both the agent and flow paths, so the backend sees the identity with no change to the wire format.

const plugin = createPreChatPlugin({ fields }); const controller = initAgentWidget({ plugins: [plugin], contextProviders: [plugin.contextProvider], }); plugin.attach(controller); // host-closure controller pattern

Storage and privacy

ctx.storage is synchronous localStorage, namespaced by persistState.keyPrefix and the plugin id. With persistState: false it downgrades to an in-memory map, so the form re-asks on every load, which is the right privacy-mode behavior. Values land in plain localStorage, so a plugin capturing anything it considers sensitive should take its own store as an option; this one accepts storage for exactly that.

Fields are host-declared

Validation stays client-side and minimal: required fields and an email shape check. Hosts declare their own set, mirroring the commercial widgets' field pickers.

createPreChatPlugin({ fields: [ { name: "name", label: "Name", type: "text", required: true }, { name: "email", label: "Email", type: "email", required: true }, { name: "topic", label: "Topic", type: "select", options: ["Billing", "Technical help"] }, ], })
