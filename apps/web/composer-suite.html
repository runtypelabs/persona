02Overflow menu

Three icon-only host actions ship with presentation: "auto", as do the three mode toggles, and one action ships with presentation: "overflow" so it always lives in the menu. Narrow the composer below the collapse width and every auto control folds into the + trigger.

The threshold is measured against the composer footer's content box, not the window, and it is re-evaluated by a resize observer. Narrow the browser window, or switch the preview to launcher mode where the panel is about 420px, to watch the fold happen live.

04Locked versus send blocked

Each lock carries a reason that renders in the composer status region. inputDisabled freezes composition entirely; sendDisabled leaves typing, attachments, and dictation fully available and blocks only the submission paths.

05submitKey

Applied live through controller.update(), with no remount. The editor's enterKeyHint follows it, so a mobile keyboard relabels its return key.

05bControl size

One token sizes every icon control in the action row: attachment, mention, the host action buttons, the overflow trigger, the mic, and the send button. Applied live through controller.update(). Per-control keys such as sendButton.size still win, and coarse-pointer devices floor the hit area at 40px.

06Attachment upload adapter

The fake adapter takes about 2.5 seconds and reports progress the whole way, so the tile sits in its uploading state and the send button stays gated until it settles. Turn the switch on, attach a file, and the tile flips to an error state with a retry affordance; the switch clears itself so the retry succeeds.

07Draft persistence

Type something, optionally pick a model and a mode, then reload this page. The draft, the model, the modes, and any quote come back. Sending clears the stored draft.

Attachments are never part of a persisted draft: no file handles and no upload credentials go to storage.

08Submitting while streaming

This page runs streamingSubmitBehavior: "defer-one". Send a message, then keep typing while the reply streams and press enter. The draft clears, a pending card appears above the composer, and it sends itself when the turn completes. A second queued submit is refused rather than replacing the first.

The demo backend streams slowly on purpose so the pending card is easy to reach.

09Edit, regenerate, and quote

Send a message, then hover it. A user bubble offers edit and quote; the last assistant reply offers regenerate. Editing resubmits from that message and replaces the tail: this release keeps no branches.

Edit is offered on text-only user messages. A message with attachments, mentions, or hidden model content is left alone rather than silently losing that context in a textarea.

Composer suite

One submission path

Every send, whether it comes from the form, the enter key, a suggestion, dictation, a plugin composer, or the controller, runs the same steps against one immutable snapshot. onBeforeSend sees that frozen snapshot after eligibility checks and before the user message is appended. Returning false, throwing, or aborting leaves the draft, the attachments, and the mention chips intact for a retry.

initAgentWidget({ composer: { onBeforeSend: (snapshot, { signal }) => { if (snapshot.text.includes("blocked")) return false; return { text: `${snapshot.text}\n\n(signed)` }; }, }, });

Selection is state, not authority

The model list and the mode list are a catalog in config; the live selection lives in composer state. Choosing a model never writes back to config and never mutates config.agent. Each send snapshots the selection into composerOptions on the wire, and each transport decides what it means: a custom backend sees the field as-is, the proxy strips it unless the route opts in, and client-token mode does not send it at all because that route's agent is pinned server side.

composer: { models: [{ id: "atlas-2", label: "Atlas 2" }], selectedModelId: "atlas-2", // initial only modeGroups: [{ id: "answer-style", selection: "single" }], modes: [ { id: "concise", groupId: "answer-style", label: "Concise" }, { id: "deep-dive", groupId: "answer-style", label: "Deep dive", persistence: "once" }, ], }

Persona attaches no meaning to a mode id. A tool, a persona, a reasoning setting, and a vendor effort level are all the same thing here: an id the backend maps.

The overflow menu is a presentation

The + menu is never a second registry. Every item in it was already contributed by core, host config, or a plugin. bar stays in the row, overflow always lives in the menu, and auto starts in the row and folds in under the width policy. Folding built-ins is always explicit: enabling the menu does not move the attachment or mention affordances by itself.

actionOverflow: { enabled: true, collapseAutoActionsBelow: 560, includeBuiltIns: ["attachments"], }

Locked is not send blocked

inputDisabled locks composition: text editing, attachment intake through the button, paste and drop, mention triggers, dictation, suggestion selection, and every submission path. sendDisabled leaves all of that available and blocks only submission, so dictation still lands a transcript in the composer without auto sending. Streaming sets neither: the send button becomes stop, which is not a submission.

The upload adapter owns the file

Without an adapter, Persona converts a picked file to a base64 content part in the browser. With one, the host takes ownership: add resolves with the content part that gets sent, reporting progress along the way, and the tile shows an uploading state until it settles or an error state with a retry if it rejects. The signal aborts when the tile is removed, the composer is cleared, or the widget is destroyed.

attachments: { enabled: true, adapter: { add: async (file, { signal, onProgress }) => { const url = await upload(file, { signal, onProgress }); return { type: "image", image: url, mimeType: file.type }; }, remove: (part) => releaseRemoteFile(part), }, }

Drafts ride the conversation payload

An unsent draft is written debounced and flushed on destroy and on page hide, through the same storage adapter that owns conversation scoping. Text, mention tokens, inline segments, the model and mode selection, and the quote all restore. Attachments do not: a persisted draft never holds file handles or upload credentials.

Defer, do not drop

Under defer-one, a submit during a stream captures one immutable snapshot, clears the draft, and shows a pending card. It auto sends when the assistant turn completes. An explicit stop or a stream error leaves it pending so nothing is lost, and a second submit while one is queued is refused rather than replacing it. The interrupt policy is a client-token capability; every other transport falls back to block with a debug warning.

Public state, private internals

controller.getComposerState() and the persona:composer:state event carry the same readonly snapshot: text, attachments, mention refs, model and mode selection, quote, any pending submission, phase, and the two lock flags. It never exposes the session, the attachment manager, DOM nodes, unresolved files, or mention finalizers, so a host can observe the composer without holding anything it should not.

Mentions and commands ride the same composer

Context mentions are nouns and slash commands are verbs, but they share one menu engine and one composer. The @ channel adds removable context whose resolved body reaches the model through llmAppend; the / channel dispatches a prompt macro, a client action, or a server skill. Both channels are ordinary composer actions at order 100, so they land leftmost in the start cluster and obey the overflow policy like everything else.

contextMentions: { enabled: true, display: "chip", sources: [createStaticMentionSource({ id: "docs", … })], triggers: [{ trigger: "/", triggerPosition: "line-start", allowSpaces: true, sources: [createSlashCommandsSource({ id: "commands", commands })], }], }

Ordering matters at send time. A slash prompt expands into the draft first, then the snapshot is frozen, then onBeforeSend patches it, then mention bodies resolve into the model-visible content. With the interceptor on, the echo's payload dump shows all three layers in one string.

This page is keyless

Every reply comes from an in-browser echo customFetch that emits Persona's unified streaming frames, so there is no backend, no key, and no cost. It streams slowly on purpose. The echo prints the payload it received, which is how the composerOptions and the onBeforeSend patch are proved rather than asserted.
