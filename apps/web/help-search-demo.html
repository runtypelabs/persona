Help search as a plugin

Compose, do not replace

The hook renders ctx.defaultRenderer() and appends the search card into it, so the greeting, icon, and starters keep rendering and derived visibility still governs the surface. Returning the default host is composition rather than a takeover: only a different element becomes plugin-owned content that overlays the transcript.

renderWelcome: ({ defaultRenderer, sendMessage, onCleanup }) => { const host = defaultRenderer(); host.appendChild(card); onCleanup(() => card.remove()); return host; }

Provider agnostic

The plugin takes a search: (query, signal) => Promise<Article[]> option, so Zendesk Guide, Algolia, or a static index all work the same way. Debounce, abort, and stale-response rejection live in the plugin: the core is not involved. This demo passes createStaticArticleSearch(), a filtered in-memory index with simulated latency.

Two click behaviors

resultAction: "open" renders each result as an anchor with target="_blank" and rel="noopener noreferrer". resultAction: "ask" renders a button that calls ctx.sendMessage() with a templated prompt carrying the article title and URL, so the agent answers from it. askPrompt overrides the template.

Header entry point

The search icon in the header is layout.header.trailingActions plus onAction, calling the plugin's focusSearch(). The plugin is built before initAgentWidget and handed the controller afterwards, the host-closure pattern the hook docs describe. Trailing actions render in the minimal header layout.

const plugin = createHelpSearchPlugin({ search }); const controller = initAgentWidget({ config: { plugins: [plugin] } }); plugin.attach(controller);

Optional starter promotion

With promoteResultsToStarters, the plugin also implements transformSuggestions: while results exist they stand in for the configured starters, and the originals return when the query clears. Starters re-render on config updates rather than on ctx.requestRender(), so the plugin asks the attached controller for a no-op update({}) when the result set changes.

No persisted state

Query and results are ephemeral UI, held in the plugin closure so a live controller.update() does not wipe what the visitor typed. Nothing reaches ctx.storage. Switching the welcome variant above re-runs arbitration: the old card is removed by the registered cleanup and a fresh one is built with the query intact.
