Home stack

Plugin options are read on every render, so toggling a section updates the stack in place without remounting the widget.

Conversation history

With history on, the stack shows up to three recent conversations under "Start a conversation" and the panel header gains a Messages action. Turning it off remounts the original blueprint, which is the backwards-compatible path.

The demo mounts an in-memory history provider through the source-only internal registry, so every state is deterministic and no API is involved.

Navigation

The house icon in the panel header calls showHome(). These buttons drive the same plugin and the same controller methods from outside the widget.

Renaming calls controller.update({ welcome: { title } }), which re-runs welcome arbitration so the plugin's own header picks up the new title.

Home screen, built on public surface

The stack owns the welcome host

renderWelcome returns a card stack instead of the intro card: a greeting header with an avatar, a "start a conversation" card, starter cards, static content cards, and a link list. The first plugin returning an element wins, so defaultRenderer() is simply never called here. Config is welcome: { variant: "hero", dismiss: "on-first-message" }: that hero is what the panel falls back to once the user leaves home without sending anything.

Leaving and returning

"Start a conversation" writes the view flag and calls requestRender(); the plugin then returns null, the overlay clears, and the transcript is visible underneath. The header action calls showHome(), which flips the flag back and re-renders. A plugin element renders regardless of derived visible and the host overlays the transcript while it is mounted, so home comes back over an existing conversation.

layout: { header: { trailingActions: [home.headerAction], onAction: (id) => { if (id === "home") home.showHome(); }, }, }

Three surfaces: home, messages, conversation

Home is this plugin. Messages and Conversation are core. The plugin never sees a history provider: it takes async callbacks and the host wires them to public controller methods. "See all" opens Messages with returnSurface: "home", so back and Escape land on the stack instead of the transcript.

createHomeScreenPlugin({ onStartConversation: () => controller.startNewConversation(), onOpenConversation: (id) => controller.openConversation(id), onShowConversations: () => controller.showHistory({ returnSurface: "home" }), onRetryRecent: refreshRecent, });

Transactional navigation

Every network-backed action is awaited before the surface changes. A successful start or open shows Conversation and focuses the composer; a failure stays on Home with the previous transcript untouched, restores focus to the control, and shows an inline status line. The re-enabled control is the retry, so nothing renders two competing retries.

Recent rows are a teaser, not the list

At most three rows: title, preview, and relative time in a <time datetime>. No message count, active marker, overflow menu, or delete, which all belong to Messages. Loading renders two shape-matched skeleton rows, a failure renders a compact "Couldn't load recent conversations" with Retry that never disables "Start a conversation", and a confirmed empty result omits the whole section including its heading.

Refreshing the teaser

The host calls controller.listConversations({ limit: 3 }) and pushes the result through homePlugin.update(). It refreshes when Home opens and on history:conversationOpened, history:conversationDeleted, history:cleared, history:identityReset, and history:identityStatusChanged. Ordinary refreshes leave stale rows visible; a deletion, clear, or identity reset invalidates them immediately.

Starters keep the pipeline

Each starter is rendered with ctx.renderStarter(suggestion), so onSuggestionSelect, the cancelable persona:suggestion:* events, and send/fill semantics all still apply. The plugin leaves home from its own onSuggestionSelect hook at a low priority, so a hook that cancels the selection keeps the user on home.

View state

Whether the user has left home lives in ctx.storage, the synchronous per-plugin store namespaced by persistState.keyPrefix plus the plugin id. Under persistState: false (this demo) it degrades to memory, so every reload starts on home. With storage on, a returning visitor lands where they left off, and a restored transcript never gets covered: an unset flag plus derived visible: false means the conversation wins.
