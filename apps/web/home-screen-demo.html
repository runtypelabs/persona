Home stack

Each toggle updates the stack in place. Options are read on every render, so nothing remounts.

Conversation history

History adds recent conversations to the stack and a Messages action to the header. Turning it off remounts the original blueprint.

The demo mounts an in-memory history provider, so every state is deterministic and no API is involved.

Navigation

The house icon in the panel header calls showHome(). These buttons drive the same controller methods from outside the widget.

Renaming calls controller.update({ welcome: { title } }); the greeting picks it up on the next render.

The header has no new-conversation icon (clearChat: { enabled: false }): Home and Messages own conversation creation, so the header only navigates and dismisses. Keep it when history runs without a Home screen.

How it works

Home replaces the welcome card

Everything on this page uses the public API: render hooks, the plugin contract, and controller methods. renderWelcome returns a card stack instead of the intro card. The first plugin returning an element wins, so defaultRenderer() never runs here. The stack is:

  • a greeting header with an avatar
  • a "start a conversation" card
  • starter cards
  • static content cards and a link list

Config keeps a fallback: welcome: { variant: "hero", dismiss: "on-first-message" } is what the panel shows if the user leaves home without sending anything.

Leaving and returning

"Start a conversation" flips a view flag and re-renders. The plugin returns null, the overlay clears, and the transcript underneath becomes visible.

  • The header's house action calls showHome(), which flips the flag back.
  • A mounted plugin element overlays the transcript, so home returns on top of an existing conversation.
layout: { header: { trailingActions: [home.headerAction], onAction: (id) => { if (id === "home") home.showHome(); }, }, }

Three surfaces: home, messages, conversation

Home is this plugin. Messages and Conversation are core.

  • The plugin never sees a history provider: it takes async callbacks, and the host wires them to public controller methods.
  • "See all" opens Messages with returnSurface: "home", so back and Escape land on the stack instead of the transcript.
createHomeScreenPlugin({ onStartConversation: () => controller.startNewConversation(), onOpenConversation: (id) => controller.openConversation(id), onShowConversations: () => controller.showHistory({ returnSurface: "home" }), onRetryRecent: refreshRecent, });

Navigation waits for success

Every network-backed action is awaited before the surface changes.

  • Success: show Conversation, focus the composer.
  • Failure: stay on Home, keep the transcript, restore focus, show an inline status line.
  • The re-enabled control is the retry, so there are never two competing retries.

Recent rows are a teaser, not the list

Home shows at most three rows: title, preview, and relative time in a <time datetime>. Anything heavier belongs to Messages: message counts, active markers, overflow menus, delete.

  • Loading: two skeleton rows, shape-matched to real rows.
  • Failure: a compact error with Retry; "Start a conversation" stays enabled.
  • Empty (confirmed): the section and its heading disappear entirely.

Refreshing the teaser

The host calls controller.listConversations({ limit: 3 }) and pushes the result through homePlugin.update(). It refreshes when Home opens and on:

  • history:conversationOpened
  • history:conversationDeleted
  • history:cleared
  • history:identityReset
  • history:identityStatusChanged

Ordinary refreshes leave stale rows visible. A deletion, clear, or identity reset invalidates them immediately.

Starters behave like normal suggestions

Each starter renders through ctx.renderStarter(suggestion), so everything that applies to a suggestion chip still applies here: onSuggestionSelect, the cancelable persona:suggestion:* events, and send/fill semantics.

The plugin leaves home from its own low-priority onSuggestionSelect hook. A hook that cancels the selection keeps the user on home.

Remembering where the user left off

Whether the user has left home lives in ctx.storage, the per-plugin store namespaced by persistState.keyPrefix plus the plugin id.

  • persistState: false (this demo): memory only, so every reload starts on home.
  • With storage on: a returning visitor lands where they left off.
  • A restored transcript is never covered: an unset flag plus derived visible: false means the conversation wins.
