Support full-duplex (speech-to-speech) voice calls, such as GPT-Live, in the built-in Runtype voice provider. The provider now declares `voiceCapabilities=full-duplex-v1` on the voice WebSocket. It handles `session_config`, turn-keyed `transcript_update`, `delegation_started`/`delegation_completed`, and `audio_clear` (barge-in) frames. In a speech-to-speech session, reply audio plays continuously, and "speaking" ends when the queued audio has played. A stopped reply is also cancelled on the server.

Voice transcripts that carry a `turnId` are now reconciled by `(turnId, role)`. Each pair keeps one chat bubble that updates in place. Overlapping turns stay separate. A bubble whose transcript carries a `startMs` sorts above any bubble from the same call that started later, so a user transcript that arrives late still renders above the reply it prompted. No empty assistant placeholder is injected; the typing indicator covers the wait. Transcripts without a `turnId` keep the existing alternating behavior. After a stop, a later reply (for example an agent answer that the stop didn't cancel) now gets its bubble while its audio plays.

Client delegation: with the new `voiceRecognition.provider.runtype.clientDelegation` option (default `true`), a full-duplex call hands the agent turns that the voice model delegates to the widget's normal chat pipeline. The provider declares `clientCapabilities=client-delegation`. When the server confirms, each `delegation_requested` turn is submitted as the visitor's message, reusing the transcript bubble so the request is shown and sent once. The answer streams in as a regular assistant message, with tool and approval UI, WebMCP page tools, and history, and goes back to the voice model as `delegation_result` to be read aloud. Its spoken read-back is not added as a second bubble, and browser text-to-speech skips it. In such a call, the voice model's own speech, and anything the visitor said that wasn't submitted, shows as display-only captions (the new `voiceCaption` message flag). Captions are never sent to the agent, so the delegated request is always the last message in the chat request. A turn that arrives while another chat turn is streaming waits for it. Servers that don't confirm client delegation keep today's server-side behavior. Separately, when the server announces `contextFrames` in `session_config`, the widget sends the voice model one `context` frame, whether delegation is on or off. The frame holds the chat history as of call start and the new `callContext` option. It is sent when the visitor finishes their first utterance (or at the first delegation, if that comes first). The voice model tends to answer context that arrives earlier: before anyone speaks, or partway through the visitor's sentence. Older servers receive neither new frame.

`VoiceProvider` gains an optional `setSessionBridge(bridge)` method, and transcript metadata gains `startMs`, `endMs`, and `caption`. New exported types: `VoiceSessionBridge`, `VoiceDelegationRequest`, `VoiceDelegationResult`, and `VoiceTranscriptMetadata`.

`VoicePlaybackEngine` gains an optional `setContinuousMode(enabled)` method. The provider calls it for speech-to-speech sessions. In continuous mode, the worklet player and `AudioPlaybackManager` release audio held below the prebuffer waterline after one waterline of input silence, so a short reply still plays without an end-of-stream signal. Custom engines without a prebuffer can omit the method.

The realtime provider now re-registers its playback-drained callback for every reply, so later replies also return the status to "listening". `AudioPlaybackManager.flush()` now ignores the late `onended` events of the sources it stopped, so the next reply is no longer reported as finished early.

The Runtype voice provider now captures from the moment the microphone opens instead of waiting for the voice socket. Audio recorded while the socket handshakes is held, capped at 8 seconds with the oldest dropped first, then sent in order once the socket opens. On a slow upgrade, the visitor's first words used to be lost. The held audio is discarded if the call ends, errors, or closes before the socket opens.
