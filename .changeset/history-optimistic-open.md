Open conversations from the Messages list without waiting on the fetch. Selecting a row leaves the list immediately: the header shows the conversation title from the row, skeleton bubbles stand in for the transcript, and the composer stays gated until hydration finishes. A failed fetch shows a retryable error surface with a way back to Messages. `history:conversationOpened` still fires on committed hydration, so it follows `history:closed`. New copy keys: `openConversationLoadingLabel`, `openConversationErrorTitle`, `openConversationRetryLabel`, `openConversationBackLabel`. `controller.openConversation` stays transactional: it resolves after hydration and rejects on failure.

The open-conversation skeleton uses the same renderer chain as the streaming indicator: a plugin's `renderLoadingIndicator`, then `loadingIndicator.render`, then the default skeleton. Both receive `location: "conversation-open"` (`streaming: false`); returning null falls through. Failed opens use `renderHistoryOpenError` (plugins by priority, first non-null wins, null falls through). The error context includes the conversation id, resolved copy, `retry()`, and `back()` (omitted when history is unavailable). The widget still owns the centered transcript column, the status/alert roles, and the composer gate around whatever those hooks return. Default markup moved to stylesheet classes (`persona-conversation-loading`, `persona-conversation-loading-error`, and their element suffixes) so CSS-only restyling works and the pulse respects `prefers-reduced-motion`.
