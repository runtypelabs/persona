"@runtypelabs/persona": minor

Add per-visitor conversation history for client-token mode, default off. `features.history.enabled` turns on a Messages surface listing the visitor's past conversations with server titles and previews, transactional conversation switching and resume across page loads, a durable visitor credential with cross-tab convergence and reset, verified cross-device scope via `getIdentityProof` with evidence-based scope reporting, display-projection finalization so reopened transcripts show what the visitor saw, and public controller methods and events (`openConversation`, `startNewConversation`, `clearConversationHistory`, `resetHistoryIdentity`, `history:*`, including `history:conversationStarted`). The Messages view ships as a lazily loaded sibling chunk; proxy and agent modes are unaffected.

Hosts can instead supply `features.history.provider`, a public option for a conversation history backend: an instance or a factory (called once per widget instance, so a single script-tag config can back several widgets). The history UX then runs against it in any session mode, including a custom `apiUrl` backend with no client token. Without a provider, history keeps its previous behavior: the built-in Runtype backend, client token mode only. The provider contract is now part of the published types: `HistoryProvider`, `HistoryConversationSummary`, `HistoryConversationPatch`, `PreparedHistoryActivation`, the list, page, and delete-all option shapes, `HistoryOperationContext`, and `HistoryProviderErrorCode`, alongside the `HistoryProviderError` class and the `isHistoryProviderError` guard as value exports reachable from the script-tag global. Providers report failures by throwing `HistoryProviderError` with a `code`: the view branches on that code and never on message text. Optional capabilities stay optional, so a provider without `update` hides the rename and star affordances, and one without `resetDevice` hides "forget this device". Scope resolution respects the provider: the derived default (verified-user with `getIdentityProof`, browser otherwise) narrows to what `capabilities.scopes` advertises, while an explicit `features.history.scope` remains a hard request that fails closed with `unsupported_scope`. Reopening the last conversation after a page reload stays a host concern with a supplied provider: persist the conversation id and call `openConversation` on ready.

In panel presentation the widget keeps one persistent header: the shell header stays in place and the Messages bar (back, title, new conversation) mounts inside it. The surface navigates like a messenger rather than a sheet. The scope status lives below the bar. `features.history.showDelete` and `features.history.showDeleteAll` (both default true) hide the visitor-facing delete controls without changing storage, retention, or identity reset.

The Messages list uses a messenger layout: title and relative time on the first line, a single-line preview beneath, full-bleed hover, and a new-conversation pill. `features.history.rowAvatar` shows a host-provided mark (`true` uses the launcher icon, a string sets an image or glyph); the default is text-only unless the host supplies one. Panel rows are 60px with no dividers; the overflow trigger fades in on hover or focus. Selected rows use a wash only (no left edge marker), themed with `--persona-history-row-active-bg` and falling back through the divider chain so the wash stays visible when container and surface share a color. `--persona-history-active-marker` is removed.

`features.history.grouping` buckets the list: `"time"` (default) uses Today/Yesterday/Previous 7 days/month headings; `"none"` is one flat list in server order, the recents-style sidebar. Starred conversations keep their pinned group in both modes. The flat group's heading labels its list from the accessibility tree only, since the visible list heading directly above already names it.

The Messages rail is a conversation sidebar (`features.history.rail`, default left / 260px, `side` and `width` 200-400). While it is mounted the widget header moves into the conversation column so the rail reads as an app sidebar. It can collapse to a 52px icon column (`collapsible`, `defaultCollapsed`), float from a header-edge trigger (`collapsedBehavior: "overlay"`), and resize from a drag handle (`resizable`). Hosts can declare `rail.sections` and `rail.brand`; plugins can contribute custom-rendered `railSections`. Collapse, overlay, and width are remembered with the other `persistState` keys. The header Messages toggle hides while any rail surface is present.

The rail gets a list header by default: a "Conversations" heading (copy key `features.history.copy.conversationsTitle`) sits above the conversation groups and carries the list overflow trigger, with the scope caption beneath it as a compact "On this device" line (leading device icon; `browserOnlyTitle` default shortened from "Messages on this device"). When `features.history.rail.sections` place a nav block above the conversations, a hairline divider separates the two. The rail header title now defaults to the full text color instead of muted; themes setting `components.history.railHeader.title.color` are unaffected. Panel presentation is unchanged (the heading is sr-only there). The list heading and the muted sub-headers (date groups and rail nav section titles) are themable through `components.history.listHeading` and `components.history.groupHeading`, and both now pin every text property in the widget CSS, so bare host-page h2/h3 rules no longer restyle them. For a custom scope indicator, decorate `.persona-history-scope` / `.persona-history-scope-title` from host CSS keyed off `data-persona-history-identity`, or take over the surface with a `renderHistoryView` plugin.

Visitor-scoped conversation rename and star: the provider seam gains an optional `update(id, { title?, starred? })` capability (summaries gain `starred`); the controller exposes `renameConversation()`, `setConversationStarred()`, and `getActiveConversationId()`. Starred conversations pin into a leading "Starred" group (copy override `groupStarred`) with a star mark on the row. `titleMenu.onSelect` may return `false` to fall through to widget built-ins, the same contract as the artifact copy menu: `star` toggles the active conversation's star and `delete` runs the shell's confirm-then-delete; `rename` stays host-owned. Renames update the `titleSource: "conversation"` header binding and the open list in place, and a user-set title pins against later auto-generated titles. `layout.header.titleSource: "conversation"` binds the header title (or `titleMenu` label) to the active conversation's title, falling back to `launcher.title` while no titled conversation is open and updating when a server-generated title arrives through a history list refresh. `history:conversationOpened` now includes `title` (null when not yet known). The history view accepts an `onActiveConversationTitle` callback for title changes on the active conversation. When `titleSource` is `"conversation"` and no conversation is open, a conversation-bound `titleMenu` locks into a plain title (no chevron, no menu) instead of offering actions with nothing to act on; it unlocks as soon as a conversation is active.

Opening a conversation from the Messages list does not wait on the fetch. Selecting a row leaves the list immediately: the header shows the conversation title from the row, and the composer stays gated until hydration finishes. A failed fetch shows a retryable error surface with a way back to Messages. `history:conversationOpened` still fires on committed hydration, so it follows `history:closed`. New copy keys: `openConversationLoadingLabel`, `openConversationErrorTitle`, `openConversationRetryLabel`, `openConversationBackLabel`. `controller.openConversation` stays transactional: it resolves after hydration and rejects on failure. The conversation-open skeleton waits 250ms before taking over, so a fast fetch goes straight from the welcome or previous conversation to the loaded transcript; failed opens still appear immediately. At commit the transcript fades in briefly; reduced motion skips that. A pending open hides the welcome surface right away, from config or a `renderWelcome` plugin, and the failed-open error surface does the same. Welcome comes back when navigation lands on an empty transcript. The open-conversation skeleton uses the same renderer chain as the streaming indicator: a plugin's `renderLoadingIndicator`, then `loadingIndicator.render`, then the default skeleton. Both receive `location: "conversation-open"` (`streaming: false`); returning null falls through. Failed opens use `renderHistoryOpenError` (plugins by priority, first non-null wins, null falls through). The error context includes the conversation id, resolved copy, `retry()`, and `back()` (omitted when history is unavailable). The widget still owns the centered transcript column, the status/alert roles, and the composer gate around whatever those hooks return. Default markup moved to stylesheet classes (`persona-conversation-loading`, `persona-conversation-loading-error`, and their element suffixes) so CSS-only restyling works and the pulse respects `prefers-reduced-motion`. Leading bubbles use `--persona-message-assistant-radius` and trailing ones `--persona-message-user-radius`, both falling back through `--persona-radius-lg`, instead of a hardcoded 16px.

Header icon buttons share one control chrome (`theme.components.header.controlSize` / `controlIconSize` / `controlStrokeWidth`). The minimal header now renders clear chat and keeps close outermost. Migration note: existing embeds using `layout.header.layout: "minimal"` gain this clear-chat control on upgrade; it wipes the visible transcript in one click, so hide it with `launcher.clearChat.enabled: false` or `layout.header.showClearChat: false` if that does not suit your surface. A keyboard shortcut registry binds `features.history.rail.collapseShortcut`, `layout.header.trailingActions[].shortcut`, and plugin `shortcuts` from one `"mod+b"` declaration (nothing is bound by default). Control tooltips are themeable (`components.tooltip`), show a shortcut hint chip, and open after `tooltip.delayMs` (default 200, with `skipDelayMs`; keyboard focus is still immediate). History confirmation dialogs are themed, cover the whole widget in the artifact split, and use the widget text token. Icon-button hover washes are scheme-aware (`components.messageActions`). A plugin `renderWelcome` overlay no longer scrolls with the transcript.

"Delete all conversations" and "Forget this device" move into an overflow menu on the "On this device" caption row. The trigger stays through first load so the row does not shift, then offers whichever actions apply. `features.history.showDeleteAll` still gates delete-all. Copy key: `features.history.copy.listOptionsLabel` (default "Conversation options"). Themes targeting `.persona-history-footer`, `.persona-history-destructive`, `.persona-history-clear`, or `.persona-history-reset` should move to `.persona-history-caption`, `.persona-history-list-options`, and `.persona-history-menu-item`.

Opening or closing Messages does not change header height: the shell pins the measured height and centers the Messages bar in that box. The Messages title uses the shared header-title font (`components.header.title.fontFamily`) so a host heading rule cannot restyle it on non-shadow embeds. List skeletons match loaded row anatomy (title, timestamp, preview in the same 60px box; title-only in the rail), use the divider/border color so they show on every theme, and wait 250ms before appearing so fast loads skip the intermediate state.

`showHistory({ focus: false })` skips entry focus and `hideHistory({ restoreFocus: false })` leaves focus alone on close. Programmatic opens, including the theme editor Messages preview, keep focus where it is. Programmatic `openConversation()` and `startNewConversation()` no longer focus the composer, so a boot-time reopen (the recommended persist-and-reopen pattern) cannot scroll the host page to the widget; for a widget in a same-origin iframe the whole parent page scrolled to it on load. Interaction paths keep the messenger behavior: selecting a conversation row, retrying a failed open, and the header new-conversation and clear-chat actions still move focus to the composer. Pass `{ focus: true }` to either controller method to opt a programmatic call into focusing.

`components.history.motion` configures enter/exit animation (`enterDurationMs` default 180, `exitDurationMs` default 160, plus easing). Durations are millisecond numbers; 0 disables that leg. CSS entrance, the fallback cleanup timer, and the WAAPI exit share `--persona-history-enter-ms`/`-easing` and `--persona-history-exit-ms`/`-easing`. `prefers-reduced-motion` still takes precedence. The theme editor exposes this as a Messages Motion section, and `PreviewScene` gains `"messages"` so the packaged preview can open the list after mount. Without a provider the packaged preview scene stays a plain conversation.
